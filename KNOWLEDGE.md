# kodex-ide Knowledge

> Empirical facts about this codebase and its runtime behavior.
> Promoted via /remember or /checkpoint. Committed with the repo.

---

- `toggleterm` Terminal:shutdown() may not fire on_close — call cleanup hooks explicitly in any reset/destroy path that calls shutdown() directly.
- Neovim Lua headless tests can stub plugins via `package.loaded['plugin.module'] = { ... }` before requiring the real module — lets the suite exercise real autocmd behavior without the full lazy.nvim stack.
- `auto-session` `get_latest_session(dir)` returns highest-mtime session in dir regardless of path — can return parent dirs (e.g. `~/dev`); filter against known project list before using.
- auto-session percent-encodes session filenames: `/home/k0d3x/dev/proj` → `%2Fhome%2Fk0d3x%2Fdev%2Fproj.vim`; use `Lib.escape_session_name(path) .. ".vim"` to locate a session file by project path.
- auto-session restore crashes with `Invalid terminal direction` (toggleterm `terminal.lua:466`) if a terminal buffer is saved into the session. `toggle_all(true)` only closes the window — the buffer stays listed and `mksession` serialises it. Must also `nvim_buf_delete(force=true)` every `buftype=='terminal'` buffer in `pre_save_cmds`.
- Renaming a toggleterm buffer via `nvim_buf_set_name(bufnr, "opencode")` in `on_open` drives the lualine statusline label (lualine reads the buffer name). Safe because toggleterm tracks the terminal via its Terminal object, not the buffer name.
- bufferline `mode = "tabs"` labels each tab by the tabpage's *active* buffer — so focusing the OpenCode panel makes the tab read "opencode". To keep the tab showing the edited file, use a `name_formatter` that, when the buffer is `buftype=='terminal'`, returns the name of a `buftype==''` file window in the same tabpage (`buf.tabnr` → `nvim_list_tabpages()[tabnr]`). Statusline (lualine) still shows "opencode"; the two labels are decoupled this way.
- Dock-launch workspace flow (`project_picker.open_workspace`): FRESH project → open nvim-tree sidebar rooted at the project (`tree.open({ path = proj })`); OpenCode launches only AFTER the first real file is opened (one-shot `BufWinEnter` augroup, filtered to `buftype==''`, named, not `alpha`/`NvimTree`), seeded with that file, then focus returns to the sidebar (`vim.schedule` + set_current_win to the `NvimTree` window) so the user is not dropped into OpenCode's insert prompt. RESUMED session → a file window already exists, so OpenCode launches immediately (focus the file window first for a correct seed) and the sidebar is NOT opened.
- `tree_toggle.toggle_at_cwd` (`<C-s>`): opens nvim-tree rooted at `vim.fn.getcwd()` (the project cd'd into by the picker), not a fixed `~/dev`. Uses `api.tree.is_visible()` to decide open-vs-close instead of a one-shot `first` flag.
- nvim-tree pins its root to the cwd it was FIRST initialised with (Neovim's startup cwd, e.g. `~/dev`); `tree.open({ path = X })` does NOT re-root it. To show the project dir you must call `api.tree.change_root(path)` after `tree.open()`, and/or set `sync_root_with_cwd = true` (+ `respect_buf_cwd`, `update_focused_file.update_root`) so the root follows `:cd`.
- auto-session `restore_session()` runs `edit <file>` non-interactively, so a stale/orphan swap file throws `E325: ATTENTION` → restore ABORTS and silently disables autosave for the session. Orphans come from unclean nvim kills on session-tracked files. `pre_save_cmds` (auto-sessions.lua) already purges terminal buffers, so *clean* exits don't orphan. Before deleting a swap, recover it (`nvim -c "recover <swap>"`) and diff vs disk to confirm it's stale. Policy (2026-06-13): manual cleanup — `rm ~/.local/state/nvim/swap/*<file>*.sw?` when E325 appears; rejected `shortmess+=A` (kills concurrent-edit protection globally).
